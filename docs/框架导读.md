## 一、这个框架在干什么

一句话：**同一批遥感数据 + 同一套指标 + 同一种划分，跑不同算法，结果追加到 JSONL。**

它不负责实现算法。算法只做一件事：**给定数据，返回每个像素一个簇标签**。
评分、划分、落盘、去重、协议指纹，全部由框架统一做——这是不同方法数字可比的前提。

## 三、一次跑批的完整数据流

以 `python scripts/run_all.py --datasets Trento --methods osmagc --federated` 为例：

```
① run_all.py::main()
      │
      ├─② discover_methods()
      │     扫 methods/*.py → 找 run_<文件名> 和 run_<文件名>_federated
      │     → { "osmagc": MethodSpec(central=..., federated=..., norm="osmagc-specific") }
      │
      ├─③ load_dataset("Trento")          [common/data.py]
      │     .mat → RSDataset(cubes, gt, H, W, n_classes)
      │     提供 flatten_view(v,"F") / flatten_gt("F") / labeled_mask("F")
      │
      ├─④ view_partition(ds)              [common/partition.py]
      │     每个视图 → 一个 Client(view_idx=[v], sample_idx=None)
      │
      ├─⑤ 调用算法
      │     集中式: run_osmagc(ds, seed=0)           → (labels, detail)
      │     联邦式: run_osmagc_federated(ds, part, seed=0) → (labels, detail)
      │
      ├─⑥ evaluate(gt[mask], labels[mask])  [common/metrics.py]
      │     只评 gt>0 的像素；ACC 先做匈牙利置换
      │
      └─⑦ append_result(RunResult(...))     [common/protocol.py]
            一行 JSON 追加到 results/runs.jsonl
            去重键 = (dataset, method, partition, norm, seed)
```

关键点：

- **算法只拿到 `ds`（和可选的 `part`）**，不知道评分、不知道落盘。
- **评分只在 `gt>0` 的像素上做**；聚类本身用全体像素（含背景）。
- **断点续跑**：`done_keys()` 读已有结果，键相同的任务直接跳过。

## 四、五个必须理解的概念

### 1. F 序（列优先）

```python
ds.flatten_view(v, "F")   # (H,W,B) → (N,B)，第 i 行 = 第 i 个像素
ds.flatten_gt("F")        # (H,W)   → (N,)
```

numpy 默认是 C 序（行优先）。**如果算法内部用 C 序，必须置换回来**，否则标签整体错位，
指标会掉到随机水平（≈1/K）。见 `common/data.py` 顶部注释。

### 2. 有标注掩码

```python
mask = ds.flatten_gt("F") > 0
m = evaluate(gt[mask], labels[mask])
```

背景像素（gt=0）参与聚类，但不参与评分。这是 OSMAGC 论文的口径。

### 3. 诚实读出

需要随机初始化的最后一步（如 k-means），统一用：

```python
KMeans(n_clusters=K, n_init=10, random_state=seed)
```

只用 inertia 选初始化，**绝不用真值挑“ACC 最高的那一次”**。论文里常见的 oracle 选择
能虚高约 8.6 个点，本平台禁止。见 `docs/协议与规范.md` 第三节。

### 4. 协议指纹

每条结果都带：`dataset / partition / norm / seed / blas_threads`。
**比较数字前先确认指纹一致**。尤其：

- `norm`：平台默认 z-score，但 OSMAGC/ETAP/SAMVGC 用自己的预处理，分别记
  `osmagc-specific` / `etap-specific` / `samvgc-specific`；
- `blas_threads`：固定 4，改了历史结果不可比。

### 5. 线程固定

`common/__init__.py` 在 import 时调用 `threads.apply()`，把 BLAS/OpenMP 钉到 4。
实测只改线程数，ACC 能差 5.9 个点。不要改。

## 六、算法文件怎么组织（两种入口）

一个算法文件 `methods/<名>.py`，可以暴露两个函数：

```python
NORM = "my-specific"          # 可选：预处理口径，写进协议指纹

def run_<名>(ds, seed=0, **kwargs):
    """集中式入口。返回 (labels, detail)"""
    return labels, detail

def run_<名>_federated(ds, part, seed=0, **kwargs):
    """联邦式入口（可选）。part 是 Partition 对象。
    detail 必须含 comm_bytes。"""
    return labels, detail
```

自动发现规则（`run_all.py::discover_methods`）：

- 扫 `methods/*.py`，跳过 `_` 开头的文件；
- 有 `run_<stem>` → 集中式；有 `run_<stem>_federated` → 联邦式；
- 两者至少有一个即被当作一个算法。

**为什么集中式和联邦式要放在同一个文件**：如果分成两个文件（如 `osmagc_federated.py`），
发现逻辑会把 `run_osmagc_federated` 当成“该文件的集中式入口”，调用时缺 `part` 直接崩。

## 七、联邦化的三种改动位置（三个方法的对照）

| 方法 | 跨视图耦合 | 改动点 | 通信量瓶颈 |
|---|---|---|---|
| OSMAGC | 像素级求和 `Σ R_v Z_v`（dim×N） | 把求和搬到服务器 | 每轮 dim×N |
| ETAP | 锚点级（m×m）+ 张量 t-SVD | α/β 标量、F、S_v、J_v 搬到服务器 | 最后一次性 N×m 的 Z_v |
| SAMVGC | 特征融合 `Z_F = Σ Wv ⊙ Z(v)` | 融合 + K-means + 原型搬到服务器 | 每 epoch 交换 M×d̂（100 轮） |

共同结论：**联邦版与集中版精度一致（gap=0），代价全在通信量。**

## 八、结果文件怎么读

`results/runs.jsonl`：每行一条 JSON。

```bash
# 看所有结果
cat results/runs.jsonl

# 只看某个方法
python -c "
import json
for l in open('results/runs.jsonl', encoding='utf-8'):
    r = json.loads(l)
    if r['method'] == 'osmagc':
        print(r['dataset'], r['partition'], r['ACC'], r['extra'].get('comm_bytes'))
"
```

字段：

- `partition`：`none`（集中式）/ `view`（视图划分）/ `2x2` 等；
- `n_clients`：客户端数，集中式=1；
- `norm`：预处理口径；
- `extra`：方法自定义（超参、`alpha`、`comm_bytes`、`lossless_max_dH` 等）；
- `status`：`ok` / `error`（失败时 `note` 有错误信息）。

`results/verify_osmagc.jsonl` / `verify_etap.jsonl`：无损性验证记录，含 `lossless_max_dH`。

## 十、常见坑

1. **C 序**：算法内部用 numpy 默认 reshape → 标签错位，指标≈1/K。
2. **在最后一步做后处理平滑**：禁止。那是另一个方法。
3. **用真值挑轮次/挑初始化**：禁止。
4. **改线程数 / `COL_CHUNK` / `n_init`**：协议指纹变了，历史结果不可比。
5. **`detail` 里放 ndarray**：落盘会失败。`run_all._jsonable` 会丢弃，但最好自己只放
   int/float/list/dict。
6. **联邦方法漏 `comm_bytes`**：`run_all` 会打印警告，且无法比较通信代价。

## 十一、下一步可以做什么

- 加算法：复制 `methods/_template.py`，实现 `run_<名>`，跑
  `python scripts/run_all.py --methods <名> --datasets Trento`。
- 加联邦版：在同一文件里实现 `run_<名>_federated(ds, part, seed)`，
  `detail` 带 `comm_bytes`，跑 `--federated`。
- 验证无损：仿照 `scripts/verify_osmagc.py`，对比集中式/联邦式的中间结果。
